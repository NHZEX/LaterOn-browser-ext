# 08：发布中断、重启与晚到写保护

Status: ready-for-agent

ITER: ITER-007

**What to build:** 用户能在发布中断后重新手动同步，确认到底传出了哪个版本；旧索引晚到时不把已知新版本悄悄降回旧版本，不能验证安全时明确暂停。

**Blocked by:** [05：加入已有库并手动同步新增收藏](05-join-and-sync-additions.md)。

- [ ] 真实后台跨重启使用轻量待发布记录，而非持久化完整快照。故障夹具覆盖快照已写但索引失败、快照超时却已落盘、快照缺失或摘要不符、后台重启。原发布已在有效索引中得到确认时不重复写；仅在核验快照身份与摘要、当前绑定及索引后，确认原发布未被更高代次取代才重发原索引。重新发布新状态时只分配高于本机已分配上界和可信远端代次的新代次，不以不同内容覆写旧代次。
- [ ] 同一设备解绑并重绑同库不会复用已发出的代次；验证发现更高代次时不主动重发确认过时的索引，无法安全推进则暂停。新代次不能撤回已在途的写，晚到覆盖仍按下述故障门禁处理。
- [ ] 重试只确认经核对的发布内容。后台中断或上传期间新增的本机编辑仍待同步；仅快照写成功或暂不能确认索引时，设置页不报已发布。
- [ ] 两配置真实链路让第 7 代索引在第 8 代成功后晚到覆盖，包括解绑前已发出的写。发端回读或下轮重检发现倒退后安全修复，不能确认则暂停；见过并验证第 8 代的对端在重启后也拒绝第 7 代，不回退本机收藏。
- [ ] 测试显式区分已见新代次与从未见过的客户端；本票不把对端高水位或单次发端回读当成新设备的服务保证，未通过启用门禁的服务保持不可用。
