# 07：同步删除与主动重新收藏

Status: resolved

ITER: ITER-007

**What to build:** 用户可以删除一张合并卡片并把删除传到另一端，而不会误删随后才收到的收藏。真正重新收藏时有新 ID；被删除传播覆盖的本机手写值仍可找回。

**Blocked by:** [06：双向编辑标题与摘要，替换旧裁决](06-sync-text-and-retire-review.md)。

- [x] 删除按确认开始时所见的原始成员 ID 落删除记录：同时看见 A、B 才一并删除，确认期间到达的新成员不计入。旧快照重放不能复活已删除 ID。
- [x] 通过真实删除和同步流程重现「先合并 A/B 再处理只删 A」与「先处理只删 A 再收 B」；两种顺序保留 B 的字段、修订和本机关联，完整同步状态及 `stateHash` 一致。规范展示 ID 切回 B 后，验收 B 的手动封面、续读位置和当前列表排序槽位仍可用。
- [x] 主动重新收藏同 URL 得到新 ID C，任何旧删除记录不覆盖 C。删除传播替换的本机手写值可在设置页找回，覆盖已发布与未发布两种状态；仍不做删除记录回收。

## Answer

收藏库、侧栏及批量删除均在打开确认框时固定原始成员；解绑重绑后拒绝旧确认。手动同步与确认加入应用同一套删除和本机关联清理，加入预览显示将移除的数量。验证方式见 [WebDAV 同步专项测试](../../../tests/browser/README.md#首份-webdav-同步快照)。普通构建仍不开放同步。
