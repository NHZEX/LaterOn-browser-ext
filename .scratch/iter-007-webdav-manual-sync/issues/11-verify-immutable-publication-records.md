# 11：验证不可变发布记录，阻止首次接入降代

Status: resolved

ITER: ITER-007

**What to build:** 在隔离构建中，让新设备即使遇到旧发布晚到，也能接入同一设备已发布的较新完整快照。沿用 [候选协议](../../../docs/adr/0005-publish-immutable-webdav-sync-records.md)；先跑环回浏览器回归，通过后把实服复验交回 [启用门禁](10-qualify-target-webdav.md)。不打开普通构建入口，不迁移已有目录，不碰 ZIP 备份。

**Blocked by:** [08：发布中断、重启与晚到写保护](08-resume-and-reject-late-head.md)、[09：无变化短路与旧快照清理](09-skip-unchanged-and-clean-snapshots.md)（均已完成）。

- [x] 用真实扩展和隔离浏览器把第 7 代发布请求挂起，解绑并重绑同库后确认第 8 代，随后实际放行第 7 代。两条记录都可见；全新配置的预览与确认均取得第 8 代。已见第 8 代的配置重启后再次同步，不回退；列举顺序打乱、代次跨 9/10 时仍选数值最大者。
- [x] 模拟快照已落盘但发布记录尚不存在、记录成功但发端没收到回执、旧意图过时及中途新编辑。孤立快照不参与接入；重启只确认匹配的发布或使用新代次，不以新内容改写旧路径。不一致的同代发布记录不择一继续，已发请求之外的旧绑定工作不影响新绑定。
- [x] 让选中的发布记录或快照在读取时真实返回 `404`，只允许整轮额外发现一次并验证严格更新的代次；若仍缺失或最高记录损坏，停止且不降代、不落盘、不发新发布。另验证列举达限、显式不完整、漏掉已知设备或已确认代次时也不合并；无提示漏列对新设备不可检测，覆盖其入口资格判定，不用夹具通过冒充协议能识别它。
- [x] 从真实请求日志验证稳态只列目录并读取各设备选中的小记录，不拉快照也不写远端；发布后依序清理已知本设备旧记录和快照，确认清理失败可重试、不会删除当前代、待确认代或他端对象。旧协议、混合目录和错误库身份不能被当成空目录；旧备份的恢复路径保持独立。

## Answer

隔离 Chromium 回归确认：第 7 代晚到后，第 8 代记录未改变，首次和重启接入都保留第 8 代。发端还验证了单文件可读但目录漏列时不会确认发布。执行方式见 [浏览器专项测试](../../../tests/browser/README.md#首份-webdav-同步快照)；代表入口实测和其他入口的手动试用判定见 [工单 10](10-qualify-target-webdav.md)。
