# 09：无变化短路与旧快照清理

Status: resolved

ITER: ITER-007

**What to build:** 已收敛的浏览器配置再次手动同步时不重复传输快照。旧快照可尽力清理，同时读取旧设备索引的对端仍有机会追到新快照。

**Blocked by:** [08：发布中断、重启与晚到写保护](08-resume-and-reject-late-head.md)。

- [x] 在发现已完成、没有待确认发布或待重试清理的稳态下，用两配置真实链路和服务端请求记录证明只读设备索引：零下载快照、零上传快照、零重写索引。存在待确认发布时不能误走短路。
- [x] 清理只在回读确认新索引后按本机记录处理本设备的快照，当前及上一代是尽力保留的目标；不为清理列目录，不删除其他设备快照或删除记录。清理失败保留待重试，不误报已确认发布失败。
- [x] 对端读取旧索引指向的快照遇到 `404` 时，限次重读索引并校验新的引用；仍无法确认时明确报错或暂停，不以空状态合并。发现阶段碰到 `PROPFIND` 限额或不完整返回不据此判空、判设备消失。

## Answer

两套隔离配置在已验证的索引与本机状态均不变时，只列目录一次并读取设备索引。新发布确认后按本机已确认发布的记录尽力保留当前及上一代；删除失败留待下次手动同步，不影响已确认发布。没有本机确认记录的旧文件不猜测归属。快照 `404` 时只追读一次严格更新的索引，新引用仍不可验证时不合并。见 [浏览器专项测试](../../../tests/browser/README.md#首份-webdav-同步快照)；真实服务启用仍由工单 10 验收。
