# ITER-007：WebDAV 手动双向同步首期规格

Status: ready-for-agent

下文是首期需求和旧覆盖式协议的验收基线。当前发布、发现及手动试用规则以 [ADR 0005](../../docs/adr/0005-publish-immutable-webdav-sync-records.md) 为准；代表入口的实测与判定见 [工单 10](issues/10-qualify-target-webdav.md)。

## 问题陈述

我在多个浏览器配置里使用 StaySide。全量备份能恢复某个时点的收藏库，但不能把各端分别新增、编辑和删除的收藏合并起来。现有实验切片只能拉取已有收藏的标题、摘要，还要求我在卡片上逐字段裁决。我要的是主动触发的双向同步：同一网页不重复展示，已删除的旧副本不回来，我亲手写过但被自动覆盖的内容还能找回。

## 解决方案

在设置中显式创建或加入一个同步收藏库，并通过「立即同步」交换收藏的新增、标题、摘要和删除。同 URL 的收藏在界面上合为一张卡片，但每条原始收藏在同步状态里仍独立存在。标题和摘要自动收敛；旧表单草稿与被同步覆盖的本机手写值，在本机设置页只读找回。同步快照与全量备份分开，不能通过同步的方式覆盖恢复整库。

## 用户故事

1. 作为第一次使用同步的用户，我希望显式创建同步收藏库，以免把错误路径、断线或不可读误认为一个空库。
2. 作为加入已有同步收藏库的用户，我希望先核对要加入的库、预览首次合并，并可取消，以便在确认前不改动两端的收藏。
3. 作为已有本机收藏的用户，我希望首次合并前保留本机恢复副本，以便出现意外时找回接入前的内容。
4. 作为希望控制 WebDAV 流量的用户，我希望只有主动点击才开始同步，以便自行选择时间和网络。
5. 作为手动同步的用户，我希望看到正在运行、完成、可重试失败及安全暂停等结果，以便知道本机改动是否已发布。
6. 作为离线收藏的用户，我希望联网后能手动发布新增的收藏，以便在另一端看到它们。
7. 作为在两端整理同一收藏的用户，我希望一端改标题、另一端改摘要时两项都能保留，以免无关字段互相覆盖。
8. 作为在不同设备修改同一字段的用户，我希望各端自动选出同一个结果，以免逐项裁决才能继续同步。
9. 作为曾经手写标题或摘要的用户，我希望同步覆盖或删除波及该值时能在本机找回它，即使那份手写内容已经发布过。
10. 作为仍开着编辑框的用户，我希望提交时只保存未冲突的字段，把过时字段的草稿留下并提示我，以免旧表单盖掉同步来的新值。
11. 作为主动清空摘要的用户，我希望空摘要能传到其他设备，以免旧摘要重新显示。
12. 作为在两端收藏同一 URL 的用户，我希望列表只显示一张卡片，同时保留各原始收藏，以免去重丢掉以后可能继续使用的内容。
13. 作为编辑合并卡片的用户，我希望修改写回我实际看到的字段所来自的收藏，以免改错成员或在成员变动后写入旧草稿。
14. 作为删除合并卡片的用户，我希望删除确认时我看到的成员，而不删除当时还没看到的成员，以免悄悄扩大删除范围。
15. 作为只删了一份同 URL 收藏的用户，我希望后来收到的另一份收藏保留原有字段，以免同步的先后顺序决定内容是否丢失。
16. 作为主动重新收藏已删除网页的用户，我希望新收藏在收到历史删除记录后仍然存在，以便真正重新收藏。
17. 作为通过设置找回内容的用户，我希望能查看、复制和清理草稿及被覆盖值，以便自己决定是否将其用于当前收藏。
18. 作为解绑后又加入同一库的用户，我希望旧绑定的下载结果和还没发出的请求不干扰新绑定，以免旧操作作用于现在的本机收藏。
19. 作为清空收藏或从全量备份覆盖恢复的用户，我希望先解除同步绑定，以免把本机恢复操作误传播到其他设备。
20. 作为在发布中途关闭浏览器的用户，我希望下次手动同步能恢复上次未确认的操作，并保留之后的新编辑，以免丢失或误报已发布。
21. 作为两端已经收敛的用户，我希望再次同步只核对设备索引，不下载或上传同步快照，以节约流量。
22. 作为连接受限或数据不可读的用户，我希望收到明确的失败或暂停反馈，不以残缺状态覆盖收藏，也仍能使用独立的全量备份。

## 实施决策

- **范围与首次接入。** 首期仅同步新增所需的基本信息、标题、摘要及删除记录；从远端新增的收藏以 URL 主机名为来源，默认为未读、未归项目。已有收藏的本机私有字段或未纳入同步的本机关联不被这些默认值重置。设置页区分创建与加入：创建生成新的 `collectionId`；加入核对已知库身份并预览。非空本机在确认首次合并后、改动前保留本机恢复副本；无法可靠识别库或读取所需状态时不以空库继续。
- **身份与提交。** `deviceId` 属于浏览器配置，不按收藏重新生成；`collectionId` 标识同步收藏库；`bindingId` 每次绑定重新生成且仅本机使用。同步库状态与发布元数据独立持久化于 `laterOnSyncMeta`，与相关收藏和找回记录走现有存储协调队列、同批提交。已有的本机编辑基线可保留手写修订，不在 `StoredItem` 复制同步状态，不改变全量备份格式。入站下载不占用写队列；合并提交时在队列内重读本机状态并复核两种 ID；每个尚未发出的出站写操作在发出前复核。解绑只拦旧回包和未发出的写，无法撤回已发出的请求。清空和覆盖恢复前解除绑定。
- **合并与投影。** 原始收藏 ID 是同步主键。存活成员独立保存，标题和摘要按字段 HLC 全序选出确定结果；设备时钟跨重启保持单调，并吸收收到的修订。空摘要统一为显式空字符串；远端值不冒充本机手写值。展示按 `normalizeUrl` 分组，先取 `savedAt` 最早、再取 ID 字典序最小的成员作规范展示 ID；各字段取组内对应的最新修订。展示 ID、派生成员集合和编辑基线不改变同步状态。规范展示 ID 变化不得丢弃仍存活成员的数据或其本机关联。
- **本机关联归属。** 合并卡片的本地手动封面和续读位置优先使用规范展示成员已有的本机关联；缺失时按同一确定性成员顺序查找其他存活成员。本地手动封面优先于自动封面，续读位置 `0` 不是缺失。读取与续写使用同一个存活成员；排序只在当前列表范围内解析已有槽位。展示 ID 切换不迁移持久化键，不改变同步状态。
- **自动补全边界。** 重复收藏的自动标题/摘要补全不产生已存在成员的新同步字段修订，也不覆盖当前已知的手写值。新收藏仍可采集元数据作为初值。区分字段是否手写和手写者是否为本机用户；自动补全不作为本机手写值写入找回记录。
- **编辑与删除。** 编辑基线记录每个展示字段的来源成员与修订；只提交用户改动且基线仍有效的字段，写回该来源。来源消失或该字段基线失效时保留当前值，记录旧表单草稿并轻提示；不影响同次提交的其他有效字段。删除合并卡片使用发起确认时可见的成员集合，按原始 ID 写删除记录；后来才到达的成员不追加进该删除。删除记录压制同 ID 的旧消息，不按 URL 泛删；主动重新收藏产生新 ID。项目级联删除和已读自动清理的同步边界见 [ADR 0001](../../docs/adr/0001-merge-webdav-collection-changes.md)。
- **找回与替换顺序。** 在实施前置阶段更新 ADR 0001，明确改用确定性合并、本机找回而非分布式待裁决候选。`overrideLog` 区分旧表单草稿和被同步合并、删除传播替换的本机手写值，后者不区分已发布与未发布。记录仅本机有界保留，支持查看、复制、清理；同一次覆盖不因重放重复产生。先让新找回入口可用并让存量旧候选可找回，再移除卡片裁决、`pendingEdits` 和 MV-Register。找回不自动复活历史 ID。
- **目录与发布。** 同步目录扁平隔离，每台设备只写自己的 `head-<deviceId>.json` 及不可变 gzip 同步快照，不依赖 ETag 或 `If-Match`。发布按「先快照、再设备索引、最后回读确认」执行。跨重启仅保留待确认的身份、代次、快照引用与摘要、索引载荷及对应本机版本，不长期保存完整快照。发送前持久化已分配的代次，同一设备重绑同库也不得复用已发出的代次。
- **恢复待确认发布。** 验证远端快照身份和摘要、当前绑定及本机已知与远端索引代次。若原发布已在有效索引中得到确认，不重复写；只在原快照匹配且能确认未被更高代次取代时才可重发原索引。无法确认旧快照或需纳入更新状态时，新代次必须高于本机已分配上界与可信的远端代次，不用不同内容覆写旧代次；无法核验索引并安全推进时暂停。只确认该发布实际包含的改动，发布过程中更晚的本机编辑仍待同步。
- **读取、短路与清理。** `stateHash` 是完整规范化同步状态的 SHA-256，涵盖成员数据、合并所需修订和删除记录，不含发布顺序、传输时间、展示投影或本机私有字段。顺序无语义的集合才规范排序；冻结格式前先证明乱序与重放收敛。按[现行不可变发布协议](../../docs/adr/0005-publish-immutable-webdav-sync-records.md#协议边界)校验目录和所选发布，仅复用已校验并合入本机的发布，新的相同摘要仍须校验。若远端有效发布已有合并后的同一状态、且本机没有待确认发布，纯接收不写远端；合并产生新状态时仍发布。回读确认新发布后，仅按本地记录尽力将本设备快照保留为「当前及上一代」；删除失败可延后重试，不为清理列目录，不在纯接收时清理。
- **晚到写与流量。** 对端持久记住已验证的设备代次，拒绝倒退；发端回读并在后续手动同步重检自己的索引，发现倒退时安全修复，不能确认安全则明确暂停。已见过新代次的对端能拒绝旧索引，不等于新加入的对端也能识别；真实服务启用不得只凭一次回读或保留两份快照。传输层按内容设置媒体类型，备份和同步共用预算口径；不要把同一次逻辑发布的超时重试一律重复按整包扣减，也不把不确定的传输当零消耗，实测区分已确认与未知的流量。

## 测试决策

- **真实双浏览器配置：主要验收入口。** 用两个隔离的 Chromium 配置加载真实扩展，通过收藏界面和设置页操作，执行真实后台、存储协调器、持久化和合并逻辑；只在 WebDAV/网络边界安排乱序、超时和故障。断言用户看见的状态、重启后状态与服务端实际请求记录。沿用仓库已有浏览器扩展测试与真实接收端测试的夹具思路，不复用旧同步浏览器测试中模拟业务合并的做法。
- **纯合并及哈希：格式冻结前置。** 用同一组输入的不同排列与旧快照重放，断言完整同步状态及规范摘要，而不只比较卡片数量或调用顺序。此入口负责穷举高风险乱序；两配置验收仅重现关键案例，不另写一套合并规则。

| 门禁 | 验收证据 |
| --- | --- |
| 首次接入与隔离 | 创建、预览后取消、确认加入已有库；非空本机先有恢复副本。错误库身份、坏快照或不完整发现不能被当成空库或触发破坏性写入。全量备份仍可独立使用。 |
| 字段合并与找回 | 不同字段两端并发编辑可同时落盘；同字段自动选出同一结果，已发布和未发布的本机手写败选值都可查。旧表单冲突字段保留当前值并留下草稿；删除传播可找回手写值。验证显式空摘要，以及一端离线自动补全、另一端手写后，手写值不被自动补全覆盖，自动值不入找回记录。 |
| 成员与删除乱序 | 同 URL 的 A、B 独立新增，删 A 时未见 B。比较先合 A/B 后处理删 A、先处理删 A 后收 B，及旧快照重放：B 的字段、修订、全量同步状态和 `stateHash` 一致。B 原有的封面、续读及本地排序槽位在 A 成为展示 ID 后及只删 A 后仍可用。另验已见成员的删除不复活，新到成员和主动重收的新 ID C 不误删。 |
| 中断、重试及晚到 PUT | 模拟已写快照但索引失败、快照超时却已落盘、快照缺失或摘要不符、后台重启和期间新编辑。只确认实际发布版本；重启和同库重绑不复用已发代次。让第 7 代在第 8 代发布成功后晚到覆盖，包括解绑前已发出的写；见过第 8 代的对端拒绝倒退，发端能够识别并修复或暂停。另验证未见第 8 代的客户端不会被未经验证的安全假设放行。 |
| 解绑后重绑同一库 | 延迟旧下载及旧出站准备，在解绑后重绑同一 `collectionId`；旧回包不落盘，旧的未发出写不产生请求。清空或覆盖恢复触发同等隔离。 |
| 无变化、清理与 404 | 收敛后再次同步只读设备索引，零快照下载、零快照上传、零索引写；遇到旧索引所指快照 404，重读索引后限次恢复。确认清理不早于索引回读、不会删他端文件，失败不会被当作同步数据丢失。 |
| 目标入口手动试用 | 完整协议回归和代表入口实测不按服务商重复。坚果云直连和 OpenList 均默认关闭；拟试用的具体入口只在专用空目录验证「发布确认 → 全新配置接入 → 核对代次及新增收藏」。未测或未通过不开放该入口，不阻塞后续开发。 |

## 不在首期范围

- 自动同步或后台轮询、增量日志、删除记录回收、卡片内逐字段裁决或跨设备找回历史。
- 项目、项目归属、阅读状态和位置、自定义顺序、图片附件等字段的跨设备同步；改变全量备份格式。
- 启用覆盖式设备索引，或将不可变发布记录的手动试用视为默认开启或正式支持所有 WebDAV 入口。

## 补充说明

- 这是 ITER-007 第二阶段的首期可实施范围，不是现有实现状态：独立全量备份已落地；旧标题/摘要单向接收切片不是手动双向同步的完成依据。
- 实施顺序：修订 ADR 并固定门禁 → 建找回入口与真实合并链路，再移除旧裁决 → 通过双配置回归及代表入口实测 → 有可用入口时冒烟后手动试用。后续字段、自动同步和长期清理策略另行决定。
