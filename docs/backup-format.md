# 本地备份与导入

运行时代码按职责归档：

- `src/backup/core.ts`：备份格式、字段白名单、关联校验、本机数据正规化、合并与 ID 映射；无浏览器 API。`wxt/entrypoints/backup-core.ts` 编译为根级 `backup-core.js`，为旧后台保留 `LaterOnBackup` 接口。
- `src/backup/background.js`：导出、预览、确认提交、清空收藏；构建后仍使用包内 `modules/backup/background.js` 地址。
- `src/backup/client.ts`：设置页与后台之间的带类型消息接口，继续使用原备份协议；文件内容的运行时校验由后台执行。
- `wxt/entrypoints/settings/BackupPanel.vue`：设置页的文件选择、下载、模式选择与确认交互；弹窗由同目录 `SettingsDialog.vue` 和 `useDialog.ts` 管理，随 WXT 页面编译。
- `src/storage/coordinator.ts`：后台共享写入队列和具体业务操作；基于最新存储计算修改，通过 WXT 输出 `storage-coordinator.js`。
- `src/storage/client.ts`：复用页面读取初始化数据代次，向后台发送具体操作，不保存可写快照；`wxt/entrypoints/storage-client.ts` 保留缓存清理、页面刷新和提示交互，输出 `storage-client.js`。
- `src/storage/contracts.ts`：共享存储键、命令与结果类型及消息结构校验；本机旧记录类型与严格备份格式分开建模。

已迁移的纯逻辑放入 `src/`，通过 WXT 编译；旧模块按资源清单复制，现有页面和内容脚本暂时保留原路径。测试与文档不打包。

## 文件格式

新导出使用 `format: "lateron.collection"`、`version: 1`、`appVersion`、ISO `exportedAt`，业务数据放在 `data` 中：

| 字段 | 内容 |
| --- | --- |
| `items` | 网页记录，含阅读状态、完成时间及手动编辑标记 |
| `projects` | 按数组顺序保存项目，含归档、置顶、备注、封面与封面组合 |
| `covers` | 网页 ID → 上传图片 data URL；默认导出为空，勾选「包含图片数据」时保留 |
| `order` | `all`、`unfiled` 或项目 ID → 网页 ID 列表 |
| `readingPositions` | 网页 ID → 非负整数 scrollY |

网页与项目引用、封面指针、排序范围及封面组合必须有效。未知字段不进入存储；未知格式版本拒绝导入。输入文件与导出文件上限均为 50 MiB。远程图片保存链接，不下载图片或网页正文。

默认导出不包含图片数据：清空 `covers`、网页本地封面引用或内嵌图片、内嵌网站图标和项目内嵌封面，保留远程图片链接与封面组合 ID。设置页可勾选「包含图片数据」导出完整封面；两种方式都不修改本机收藏。导入无图片的备份后，网页和项目图板使用 LaterOn 默认占位图；项目导航缩略图优先使用可用网页封面，没有可用封面时显示项目名首字占位。占位图随扩展提供，不写进备份。

保留读取本项目旧 `lateron-backup` v2 文件标准字段的能力：内嵌封面转为独立封面，旧 `read` 转为三态阅读状态；旧文件没有阅读位置。没有 fork 专用协议、同步元数据或迁移分支。

## 导入语义

合并按共用的 URL 规范化规则去重，已有网页保留本机内容、项目、封面、顺序和阅读位置。相同 ID、创建时间的项目复用本机项目；同名但创建时间不同的项目不会仅凭名称合并。冲突 ID 重新生成，所有新增网页的项目、封面、阅读位置、排序及封面组合随之映射。同名同创建时间用于识别上次因 ID 冲突而重建的项目。

覆盖恢复替换五组业务数据，保留本机设置（包括自动清理开关和天数）。导入不会重置已读网页的完成时间；关闭自动清理时保留已读网页，开启时按本机期限清理，归档项目适用同一规则。临时界面状态、待抓取批次、诊断与侧栏缓存不进入备份。

预览不写入存储。界面持有原文件、预览时间与收藏快照 SHA-256；后台确认时重新校验。覆盖模式要求快照仍相同，合并模式基于最新收藏重新计算。预览可跨 service worker 休眠，十分钟后需重新预览。

提交通过共享后台队列，一次写入五组数据和新的收藏 epoch。全屏页与侧栏清理缓存并重新加载；携带旧 epoch 的页面操作会失败，避免导入前尚未完成的交互作用于恢复后的数据。epoch 是随机代次标识，普通编辑不递增。

## 核心数据写入边界

页面可以直接读取 `chrome.storage.local` 显示内容，通过 `storage.onChanged` 更新界面。页面写入使用 `LaterOnStorage.run(action, fields)`：创建项目、修改项目字段、设置置顶、按锚点移动项目或收藏、删除项目、修改或删除收藏、迁移旧数据。后台在同一队列任务内读取最新数据、执行操作并保存；页面不再提交整份数组或映射，也不维护 `expected` 快照。

编辑只提交用户实际修改的字段；移动只提交目标 ID、范围和前方锚点 ID，因此保留其他页面新增的数据和无关字段修改。对同一字段的并发编辑按后台处理顺序生效，后处理的值覆盖先处理的值；这不是多用户编辑冲突合并系统。通知可能延迟，页面显示属于最终一致，核心写入按队列顺序处理。

收藏封面内容与 `local://` 指针在一次存储写入中保存。删除项目按执行时的最新归属级联清理收藏、封面、顺序、阅读位置和相关界面标记。旧内嵌封面和完成时间的补齐也由后台读取最新记录后迁移。主题、语言等界面偏好仍由原模块写入。

## 验证

`node tests/backup.test.js` 验证格式、含图与默认不含图片数据的往返、引用映射、重复导入、预览有效性、并发与失败恢复。

`node tests/backup-settings.test.js` 使用 jsdom 验证中英文预览、取消、两种导入模式、图片导出选项、坏文件、大小限制、下载和失败重试。

`node tests/backup-images.test.js` 验证不含图片数据的备份导入后，全屏网页、项目图板和侧栏的默认占位图，以及图板远程图片加载失败时的回退。现有测试使用独立 Node 脚本；DOM 测试需要通过本机 Node 模块路径提供 jsdom。
