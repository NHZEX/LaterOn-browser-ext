# 本地备份与导入

格式与校验以 [备份核心](../src/backup/core.ts) 为准，预览 / 提交协议见 [后台实现](../src/backup/background.ts)，整体写入边界见 [架构](architecture.md#数据边界)。本文解释备份行为，不复制实现清单。

## 文件格式

新导出使用 `format: "lateron.collection"`、`version: 1`、`appVersion`、ISO `exportedAt`，业务数据放在 `data` 中。StaySide 沿用此格式以兼容重命名前的备份，下载文件名使用 `stayside-backup-<时间>.json`：

| 字段 | 内容 |
| --- | --- |
| `items` | 网页记录，含阅读状态、完成时间及手动编辑标记 |
| `projects` | 按数组顺序保存项目，含归档、置顶、备注、封面与封面组合 |
| `covers` | 网页 ID → 上传图片 data URL；默认导出为空，勾选「包含图片数据」时保留 |
| `order` | `all`、`unfiled` 或项目 ID → 网页 ID 列表 |
| `readingPositions` | 网页 ID → 非负整数 scrollY |

网页与项目引用、封面指针、排序范围及封面组合必须有效。未知字段不进入存储；未知格式版本拒绝导入。设置页导入文件和导出下载文件上限均为 50 MiB；后台另对导入请求校验大小。远程图片保存链接，不下载图片或网页正文。

默认导出不包含图片数据：清空 `covers`、网页本地封面引用或内嵌图片、内嵌网站图标和项目内嵌封面，保留远程图片链接与封面组合 ID。设置页可勾选「包含图片数据」导出完整封面；两种方式都不修改本机收藏。导入无图片的备份后，网页和项目图板使用 StaySide 默认占位图；项目导航缩略图优先使用可用网页封面，没有可用封面时显示项目名首字占位。占位图随扩展提供，不写进备份。

本地共享图标表和 `icon://` 引用不进入文件格式：含图片导出先还原原始 DataURL，再执行现有校验，引用缺失时明确报错，避免生成貌似完整的缺图备份；无图片导出直接移除内部引用，不依赖图标内容。导入校验和合并完成后，按最终收藏重新生成本地图标引用并回收未使用内容；覆盖恢复可用完整备份修复本地图标表缺失。v1 文件为兼容旧版仍逐条携带图标，因此本地去重不会同步缩小备份文件，也不改变文件上限。旧应用不认识新的本地引用；如需降级，应通过新版导出的含图片 v1 文件恢复，不能直接用旧版读取迁移后的本地存储。

保留读取本项目旧 `lateron-backup` v2 文件标准字段的能力：内嵌封面转为独立封面，旧 `read` 转为三态阅读状态；旧文件没有阅读位置。没有 fork 专用协议、同步元数据或迁移分支。

## 导入语义

合并按共用的 URL 规范化规则去重，已有网页保留本机内容、项目、封面、顺序和阅读位置。相同 ID、创建时间的项目复用本机项目；同名但创建时间不同的项目不会仅凭名称合并。冲突 ID 重新生成，所有新增网页的项目、封面、阅读位置、排序及封面组合随之映射。同名同创建时间用于识别上次因 ID 冲突而重建的项目。

覆盖恢复替换五组业务数据及其共享图标表，保留本机设置（包括自动清理开关和天数）。导入不会重置已读网页的完成时间；关闭自动清理时保留已读网页，开启时按本机期限清理，归档项目适用同一规则。临时界面状态、待抓取批次、诊断与侧栏缓存不进入备份。

预览不写入存储。界面持有原文件、预览时间与收藏快照 SHA-256，快照包含共享图标表；后台确认时重新校验。覆盖模式要求快照仍相同，合并模式基于最新收藏重新计算。预览可跨 service worker 休眠，十分钟后需重新预览。

提交通过共享后台队列，一次写入变更的数据、共享图标表和新的收藏 epoch。全屏页与侧栏清理缓存并重新加载；携带旧 epoch 的页面操作会失败，避免导入前尚未完成的交互作用于恢复后的数据。epoch 是随机代次标识，普通编辑不递增。

“清空收藏”保留项目和本机设置，清除收藏、上传封面、共享网站图标、自定义网页顺序和阅读位置，同时移除项目封面组合引用并更换 epoch。

## WebDAV 备份与恢复

在「设置 → 数据与维护 → 备份与恢复」卡片的 WebDAV 区域，展开「配置 WebDAV」填写 HTTPS 服务地址、专用目录、账号和应用密码。连接设置保存在本浏览器配置中，凭据只用于向该地址认证。配置后，卡片直接显示最近备份时间、「立即备份」和「查看备份」。点「查看备份」才请求远端列表。

- 新 ZIP 将 `manifest.json` 作为不压缩的条目写入。`version` 是清单版本，`backup` 下保存数据文件名、格式和数据版本。`counts` 记录网页、项目、上传封面和阅读位置的数量。清单还记录扩展版本、导出时间及生成快照时的图片选项 `includeImages`。
- `backup.json` 使用浏览器原生压缩流压缩。下载和恢复以这个条目为准，校验 CRC-32 和数据格式，并将解压出的 JSON 限制在 50 MiB 内。没有清单的 ZIP 也可恢复。WebDAV 列表继续通过路径、文件名和目录属性展示备份信息。
- 原始 ZIP 的下载上限为 50 MiB 加 256 KiB。校验通过后，后台通过原生 `MessageChannel` 移交原始 ZIP 的 `ArrayBuffer`，设置页收到后触发保存。传递过程只用内存，下载中断时可重新下载。

- 「立即备份」可单独选择是否包含图片。自动备份由各浏览器配置分别开启，默认按 24 小时检查到期的内容变更，支持修改间隔和图片选项。自动任务用会写入备份的收藏数据计算摘要，与上次成功的自动快照比较。摘要相同则跳过上传和轮转。
- 文件位于专用目录下的 `backups/<备份来源 ID>/`，以毫秒精度的 UTC 时间和 `-auto.zip` 或 `-manual.zip` 命名。先 `PUT` 到暂存路径，再用 `MOVE` 发布。遇到同名时只为正式文件加短序号，再次尝试 `MOVE`。每次备份都从最新收藏生成快照，手动失败后可再次备份，自动失败由后台调度重试。若发布成功但响应丢失，重试可能多留一份快照。
- 备份来源目录已存在时，备份依次发出 `PROPFIND`（`Depth: 0`）、`PUT` 和 `MOVE`。首次自动备份或距上次轮转检查满 24 小时的下一次自动备份改用 `PROPFIND`（`Depth: 1`）。发布后复用该列表，为当前备份来源保留最近 7 份自动备份，同时删除超过 48 小时且符合 StaySide 暂存命名的 `.zip.upload` 文件。每删除一份增加一次 `DELETE`。清理失败仍记为备份成功，下次符合轮转条件再试。两次清理之间可能暂时超过 7 份。首次创建目录和异常重试的请求另计。
- 连接同一专用目录后可查看各备份来源的 ZIP，下载或预览合并、覆盖恢复。WebDAV 覆盖恢复前会保留本机恢复副本，可在同一面板下载。设置页支持导入本地 ZIP 和 JSON。旧 WebDAV `.json` 文件留在服务端，由用户自行删除；WebDAV 列表、恢复和轮转仅处理 ZIP。手动备份由用户删除。
- 每个备份来源默认的月流量预算为 192 MiB。上传按 ZIP 及 `PROPFIND` 等请求体的字节数估算，下载按已读取的响应字节数计量，账户实际用量见服务端。达到预算时暂停自动任务。手动操作触及预算时可确认继续，超预算提示前已经读取的数据仍计入用量。
- 服务需支持 WebDAV 的目录读取与创建、文件上传和读取、`MOVE` 发布及删除。对达到坚果云公开单次列举上限的目录，面板会提示列表可能截断，避免从不完整列表轮转。[坚果云 WebDAV 限制](https://help.jianguoyun.com/?p=2064)

## 验证入口

- [backup-core.test.js](../tests/backup-core.test.js)：执行纯格式 / 规范化核心。
- [backup.test.js](../tests/backup.test.js)：格式往返、引用映射、重复导入、预览有效性、并发和失败恢复。
- [webdav-backup.test.js](../tests/webdav-backup.test.js)：执行实际备份后台，验证独立来源、同名、响应丢失后的重试、自动轮转、流量预算和远端快照恢复。
- [backup-images.test.js](../tests/backup-images.test.js)：不含图片备份导入后，两页卡片 / 项目图板占位与远程封面失败回退。
- [icon-storage.test.js](../tests/icon-storage.test.js)：图标无损往返、导入重新去重、共享表参与预览失效检查、失败重试与清空回收。
- [release-tools.test.js](../tests/release-tools.test.js) 调用 [设置页行为 helper](../tests/helpers/verify-settings-page.cjs)：实际 WXT 页面中的预览、取消、导出与导入、坏文件和失败重试。

安装项目依赖后用 `pnpm test` 统一执行，也可 `node tests/backup.test.js` 单独运行；无需设置本机 `NODE_PATH`。测试分层见 [测试说明](../tests/browser/README.md)。
