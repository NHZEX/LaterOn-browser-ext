## 已确认的方向

| 方向 | 用户确认 |
| --- | --- |
| 优先级 | WebDAV 先独立交付备份与恢复，随后推进低频双向同步 |
| 设备范围 | 首期桌面 Chrome / Edge、多台电脑；后续考虑支持扩展的 Chromium 系手机浏览器 |
| WebDAV 同步方式 | 设备离线时继续使用本机收藏，恢复连接后双向合并。启用后自动同步，也可点「立即同步」 |
| WebDAV 验收服务 | 首测坚果云，控制请求频率和流量，为账户其他用途留出额度。OpenList 是后续可能使用的服务，按实际版本与挂载方式验收 |
| WebDAV 首期隐私 | 使用可信 WebDAV 服务和 HTTPS。用户接受服务端可读取同步数据，首期无需端到端加密 |
| 离线保存 | 同时支持正文阅读版和整页存档，二者都要保留为可用的保存类型 |
| 捕获方式 | 接受收藏后自动排队的默认建议；触发动作、保存类型都要可配置，使用方便 |
| 标签 | 一篇收藏可以有多个平级标签，标签与项目独立 |

WebDAV 的两阶段规则和服务验收标准见下文。手机浏览器和其他独立方向分别讨论。

## 当前项目事实与影响

- 正式收藏在 `chrome.storage.local`，包含网页、项目、阅读状态、封面、共享图标、排序及阅读位置；同一浏览器内部由[共享写队列](../../src/storage/coordinator.ts)协调。这不是跨设备同步协议，不能把本机的“后写覆盖”直接当作多设备冲突规则。
- 网页目前只保存元数据，没有正文快照或内容标签；搜索覆盖标题、摘要、来源和 URL，见[数据契约](../../src/storage/contracts.ts)、[备份核心](../../src/backup/core.ts)和[筛选规则](../../src/collection/filter.ts)。
- [现有备份](../backup-format.md)采用 `lateron.collection` v1 JSON，WebDAV 用 ZIP 封装。导入会筛除未知字段，解压后的 JSON 上限 50 MiB。新增标签、正文和存档必须一起设计导入导出，不能只加本地字段后假定旧备份已经能保存它们。
- [历史清理](../../src/background/maintenance.ts)会移除旧的 `contentHtml` 等正文遗留字段。新存档应有独立模型与迁移边界，不能直接复活旧字段。
- 项目继续表示网页所属的整理空间；内容标签表示可跨项目复用的主题。这里的“标签”不是浏览器标签页，也不等于未读 / 在读 / 已完成状态。

## WebDAV 分阶段交付

1. **备份与恢复**。先独立交付手动备份、自动备份和显式恢复。以坚果云实测换机恢复、请求数及流量。
2. **低频双向同步**。在备份与恢复验收后，推进两设备同步协议及其并发、冲突和断网恢复验收。

### 独立全量备份

第一阶段的文件布局、自动规则和恢复流程见 [备份说明](../backup-format.md#webdav-备份与恢复)。[独立备份决策](../adr/0002-store-webdav-backups-as-self-contained-snapshots.md)

### 共用服务与流量预算

坚果云免费版的月流量和第三方 WebDAV 请求频率分别受限。用代表性收藏规模验收实际请求数、上下行流量和频率限制下的恢复，给账户内其他应用留出空间。OpenList 按具体版本和存储驱动验收。[坚果云资费](https://www.jianguoyun.com/s/pricing) · [坚果云 WebDAV 限制](https://help.jianguoyun.com/?p=2064)

按设备估算 StaySide 的月流量，双向同步和 WebDAV 备份计入同一可调预算。达到预算时暂停两种自动任务。预计超预算的手动同步或备份先提示用量，由用户确认后继续。默认预算在测量代表性收藏规模后确定。账户用量和重置时间以坚果云的账号界面为准，WebDAV 标准的配额属性描述存储空间。[坚果云流量计算说明](https://help.jianguoyun.com/?p=29) · [WebDAV 存储配额](https://www.rfc-editor.org/rfc/rfc4331.html#section-3)

### 第一阶段备份验收

1. 在 Chrome 或 Edge 用坚果云连接测试目录，完成手动快照与有变更时的自动快照。分别测量含图片与仅收藏数据的快照体积，以及上传、列表和下载的请求数及流量。
2. 从另一浏览器配置选择并下载一份备份，预览后恢复收藏、项目、自定义顺序和阅读位置。使用含图片备份时核对封面和图标。
3. 验证无变更、断网恢复、上传中断和共用预算耗尽时的行为。中断后保留可恢复的旧备份及待备份状态，待条件恢复后继续。
4. 验证两台设备独立备份、同名时追加序号，以及响应丢失后按最新收藏重试。用短备份间隔验证 24 小时内可暂存超过 7 份，轮转随到期的下一份自动备份进行，并清理超过 48 小时的本设备暂存文件。核对手动备份和其他配置的备份仍可恢复，清理失败时新备份仍记为成功。

## 共同建议：数据留在本机，传输与附件分开

本地收藏始终可用。下表说明第二阶段的双向同步范围。第一阶段的完整备份数据见 [独立全量备份](#独立全量备份)。

| 数据 | 建议处理 | 需要补充的需求 |
| --- | --- | --- |
| 收藏、项目、标题与摘要等文字编辑、阅读状态、自定义顺序 | 进入首轮双向同步 | 用实际收藏规模测量流量，并验证下文的合并与删除场景 |
| 封面、共享图标 | 后续随收藏同步，候选为资源单独传输、校验和去重 | 失败时允许文字先可用，并显示附件待补齐 |
| 标签及网页与标签的关联 | 标签功能上线后纳入同一套同步规则 | 重名标签、同时添加 / 移除的合并方式 |
| 正文、整页存档及资源 | 快照功能上线后扩展；候选为上传可选、下载按需 | 是否默认上传两种存档、是否自动下载到每台电脑 |
| 主题、语言等少量偏好 | 首轮双向同步保留本机，后续可选原生同步或 WebDAV | 同一字段只有一个同步来源 |
| 阅读位置、筛选、侧栏宽度、当前网页、缓存、任务进度 | 首轮双向同步保留本机 | 如果以后同步阅读位置，需处理设备视口与页面布局差异 |
| WebDAV 应用密码、设备身份、内容密钥 | 由各浏览器配置本机保存 | 浏览器配置同步的候选字段见下文 |

同一收藏库建议只启用一个收藏同步后端。原生同步与 WebDAV 同时使用时，明确各自负责的字段，避免相互回灌。同步不是历史备份；误删同步到所有设备后，仍需要可恢复的版本或独立备份。

## WebDAV 首期同步方案

这是第二阶段的低频双向同步方案。设备离线时可以继续使用本机收藏。设备恢复同步并处理完冲突后，共享数据收敛。[并发合并与删除决策](../adr/0001-merge-webdav-collection-changes.md)

### 首次接入与日常使用

1. 配置服务地址、独立目录和认证，先测试连接、读写及并发保护能力；凭据不写入项目文档或日志。
2. 首次接入展示本机与远端概要。本机为空时从远端拉取，已确认远端为空时用本机数据初始化。双方均有数据时，先预览新增、重复和冲突。同名项目按各自的项目处理，用户可在预览中主动合并。用户确认后先保存本机恢复副本，再应用合并。
3. 提供“立即同步”、最近成功时间、待上传 / 下载数量、失败原因和重试入口。本机写入成功不能显示成“已同步到其他设备”。
4. 自动检查至少间隔 30 分钟，由浏览器启动、打开收藏界面或本机有待上传改动触发。空闲时停止轮询。合并频繁的本机改动，尽量只传输有变化的数据。「立即同步」用于主动发起同步。
5. 关闭同步保留本机数据；更换账号、目录或服务器视为接入另一收藏库，不能直接复用旧同步基线。

### 合并、删除与恢复

| 场景 | 首期规则 |
| --- | --- |
| A 修改标题，B 修改摘要 | 合并不同字段，保留双方改动 |
| A、B 同时修改同一个标题或移动到不同项目 | 保留双方改动并标记冲突，待处理时各设备暂时显示自己的值。可以在任一设备处理，选择结果同步给其他设备。其他收藏继续同步 |
| 单篇删除、多选删除、删除项目 | 手动删除传播到其他设备。项目级联删除限于确认时列入删除范围的收藏，确认时说明跨设备影响 |
| 删除项目时，另一台设备离线新加入收藏 | 留下该收藏，转入「等待整理」并提示用户。确认范围内的旧收藏与离线编辑按删除冲突规则处理 |
| 到期已读收藏触发自动清理 | 启用同步后默认暂停自动清理。用户明确为同步收藏库开启后，到期删除才会传播 |
| A 删除，B 长期离线后上线 | 未编辑的旧副本随删除移除。如果 B 离线期间编辑过，普通列表仍应用删除，保留 B 的编辑供用户查看和主动恢复 |
| 长期离线后，已知基线或删除记录不足 | 保留本机待同步改动，预览后重新接入。证据足够时继续正常合并并处理冲突，离线时长本身不决定同步结果 |
| 删除后主动重新收藏相同 URL | 建立新收藏，删除记录继续约束之前的收藏及其旧副本 |
| 两台电脑分别收藏同一页面 | 按现有 URL 身份规则识别并合并为一条。保留兼容字段，同一字段或项目归属冲突由用户选择 |
| 两台电脑并发修改自定义顺序 | 不同列表的排序分别保留。同一列表上的顺序有冲突时由用户选择，新加入的收藏按现有规则追加 |
| 清空收藏、覆盖恢复 | 先解除本机同步关联并保存本机恢复副本，再执行本机操作。远端数据保留，重新连接时按首次接入流程处理 |
| 合并导入备份 | 新增的收藏可以正常同步 |
| 恢复非冲突的日常误删 | 沿用现有备份恢复。跨设备回收站在后续阶段评估 |
| 远端超时、认证失败、文件损坏、未知格式 | 保留本机数据，停止错误覆盖；不能把读取失败当成“远端为空” |
| 网络恢复、浏览器退出或后台被回收 | 持久化待处理操作，恢复后幂等重试；不重复新增，不丢失已确认修改 |
| 一台设备版本过旧 | 对不认识的同步格式停止写入并提示升级，不能筛掉新字段后回传 |
| 图片或存档上传中断（后续阶段） | 未完成附件不能标为可用；恢复后补传，清理不能删掉仍被引用的资源 |

### 同步传输

协议至少需要区分远端收藏库身份、协议版本、设备身份、记录修订、删除记录和本机待提交操作。本机现有 epoch 用于拒绝旧页面命令，不直接替代跨设备版本。不能单凭设备墙上时钟解决冲突；长期离线设备及删除记录回收也必须一起设计，不能到期直接清空删除记录。

优先在实际坚果云服务上验证强 ETag 与 `If-Match` 条件提交，以及用 `If-None-Match: *` 并发创建。通过验证后采用条件写入保护提交，遇到前置条件失败时重新读取、合并并限次重试。若条件写入验收未通过，改为验证各设备独立提交改动批次的候选方案。双向同步的启用以实际服务的并发及流量验收通过为前提。[HTTP 条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)

OpenList 按实际版本和存储驱动验证并发写入。以后若同步需要登录才能读取的正文或整页存档，届时再确认服务端可见性和密钥恢复要求。[OpenList 条件写入变更](https://github.com/OpenListTeam/OpenList/pull/3066)

### 真实服务验收

1. 在独立测试目录用两台客户端读取同一版本，再提交不同内容。服务应拒绝过期的写入，并保留先提交的数据。同时创建同一远端文件时，只允许一次创建成功。
2. 如需验证独立批次方案，检查两台设备同时提交时双方批次均完整保留。模拟响应丢失并重试，确认每个批次只应用一次，并发首次接入最终识别为同一个同步收藏库。
3. 用代表性收藏规模测量首次接入、无变化检查、频繁本机编辑合并提交和失败重试的请求数及上下行流量，据此确定默认预算。两台客户端需验证离线期间的编辑、删除及排序冲突，并确认中断后继续同步时数据仍完整。

## 浏览器原生同步：能力与限制

这里指扩展的 `storage.sync`，不是浏览器书签同步，也不是让浏览器自动同步 `storage.local`。

Chrome 官方当前限制如下；统计包含键和序列化后的值，不能仅按网页条数估算：

| 限制 | Chrome 官方值 |
| --- | --- |
| 总容量 | 102,400 字节，约 100 KiB |
| 单个键值项 | 8,192 字节，约 8 KiB |
| 键值项数量 | 512；不是允许保存 512 篇完整网页 |
| 写入频率 | 每分钟 120 次、每小时 1,800 次，`set/remove/clear` 计入 |

超过限制会失败；拆键不能绕过总容量。`unlimitedStorage` 不扩大 `storage.sync` 的这些固定配额。建议首期只评估语言、主题等少量偏好，提供占用显示及限额失败提示，不放正文、图片和整页存档。若后续要支持精简收藏同步，必须单独确认字段、容量预算、分片一致性和超额时的完整性，不能静默只同步部分收藏。依据：[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。

Chrome 同步取决于用户登录、同步开关、网络和策略；离线写入不代表远端已收到。Chrome 文档描述其自身同步服务，Edge 使用其账号同步体系，因此规划不把 Chrome 与 Edge 的原生云空间当成互通渠道。Edge 支持 storage API 不等于所有发行渠道、账号及设备组合已验证；需要同浏览器两台电脑实测，另测固定扩展 ID、本地加载版 / 商店版及策略关闭同步的情况。参考 [Chrome 同步行为](https://developer.chrome.com/docs/extensions/mv2/reference/storage#storage-areas)、[Edge 同步](https://support.microsoft.com/en-us/edge/sign-in-to-sync-microsoft-edge-across-devices)、[Edge API 支持](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/api-support)。

### 配置同步实施计划

ITER-026 的候选范围为桌面扩展配置。建议在「设置 → 常规设置」提供「同步设置」开关，默认关闭。WebDAV 连接预设单独勾选。

| 浏览器云端字段 | 本机字段 |
| --- | --- |
| 主题、语言、默认排序 | 自动清理、界面临时状态和各设备的同步开关 |
| WebDAV 地址、目录、账号、备份频率、图片选项 | WebDAV 应用密码、自动备份开关、流量上限与用量、设备 ID、待上传任务和恢复副本 |

1. **先确定同步开关和首次接入。** 云端与本机有差异时显示预览，由用户选择使用云端或上传本机。关闭同步后停止收发，继续使用本机值。离线或浏览器同步不可用时仍允许本机修改，界面区分本机已保存和浏览器同步区写入结果。
2. **接入普通偏好。** 继续用现有本机设置供各页面读取。启用后，主题、语言、默认排序分别保存到 `storage.sync`。接收云端变更时只更新相应的本机字段，并复用现有的本机变化通知。语言写入统一到与其他偏好同一条入口，避免重复写回云端。
3. **再接入 WebDAV 预设。** 地址、目录和账号作为一组读取，预设同时带来频率和图片选择。收到后生成配置草稿，用户测试草稿连接并明确保存后才应用。更换服务器或账号时重新填写密码，旧连接在确认前继续使用。自动备份仍由每个浏览器配置单独开启。
4. **验证真实写入与接收。** 回归默认关闭、首次冲突选择、不同字段同时修改、离线重连、云端写入失败和关闭同步。用包含测试应用密码的本机配置确认云端写入只有候选字段，远端 WebDAV 变更未经确认时没有 WebDAV 请求。最后在同浏览器、同账号、同扩展 ID 的两台设备上分别验收 Chrome 和 Edge 的真实传递，优先验证本机加载版。

## 快照：正文阅读版与整页存档

两种产物服务不同用途，属于同一次捕获记录，可分别成功或失败：

| 保存类型 | 目标 | 不能默认承诺的内容 |
| --- | --- | --- |
| 正文阅读版 | 离线查看正文、标题、作者等可提取信息及保存成功的正文图片，采用适合阅读的排版 | 对所有非文章页面都能正确提取全文 |
| 整页存档 | 保留捕获时已加载的页面内容、样式、布局和可保存资源 | 任意交互、流媒体、未加载的无限滚动内容、所有跨域嵌入都能复现 |

“完整”应描述实际捕获范围，而不是整站下载或未来内容。仅保存远程图片 URL 不算图片已离线。用户已登录且能访问的内容可在其授权的保存动作中捕获，但不承诺绕过登录、付费或访问限制。

### 配置与入口建议

将触发方式与保存类型独立配置，避免组合成大量难懂的开关：

| 设置 | 候选选项 | 建议默认 |
| --- | --- | --- |
| 自动触发 | 关闭自动捕获；收藏成功后自动捕获 | 收藏后自动排队 |
| 默认保存类型 | 正文阅读版；整页存档；两者 | 两者 |
| 单篇操作 | 立即保存、选择本次类型、重试缺失部分、更新快照、删除快照 | 使用全局默认，一次操作即可开始 |
| 已有收藏 | 手动补存，可选择范围，展示可捕获 / 需打开原文的数量 | 不在升级后自动遍历和打开所有旧网页 |
| 批量操作 | 批量保存或重试，允许取消，限制并发并展示逐项结果 | 不阻塞收藏列表 |

“仅手动”时仍允许选定默认类型；自动关闭不影响手动入口。按站点覆盖、定时刷新和多版本保留属于后续候选，不作为“可配置”自动推导出的首期承诺。

### 保存、阅读和管理建议

- 先提交收藏，再排队捕获。失败保留链接；正文和整页分别显示排队、处理中、可用、部分资源缺失、失败等结果，并提供原因与重试。
- 捕获时核对标签页仍存在且仍为目标页面；跨页跳转、关页、冻结和未加载页面要明确反馈，不静默激活大量标签页。后台重新抓 URL 不等于获得用户当前看到的动态或登录页面。
- 保留原始 URL、捕获时间、格式版本、资源校验和、大小和缺失信息。更新失败保留旧的可用快照；先建议每种类型保留最近一次成功结果，多版本作为另一个容量需求讨论。
- 提供明确的“阅读正文”“打开整页存档”“打开原网页”入口；断网时不依赖先访问原站才能找到快照。存档与手工编辑的标题、摘要分开管理，不因重新抓取覆盖用户整理。
- 内容与资源建议独立存储，例如扩展来源的 IndexedDB；普通收藏记录保存索引和引用，避免在列表整表中内嵌大段正文 / 图片。跨存储提交需有完成标记及中断恢复，不假定与 `storage.local` 存在共同事务。
- 展示单篇和总占用，允许删除快照而保留链接。单篇 / 全局容量上限、空间不足策略、删除收藏是否同时删除存档、自动清理是否应保留存档均待确认；默认不静默淘汰用户已保存内容。
- 阅读回放隔离原站脚本与扩展能力；不把原站 HTML 直接放进高权限扩展页面，不保存表单口令和会话凭据。离线回放默认不继续访问原站获取缺失资源，缺失需明确标注。
- 导出需区分收藏信息备份与含正文 / 整页资源的完整备份；旧 50 MiB JSON 不是完整存档方案，需另行评估带清单的资源包及兼容升级。

格式先做方案验证：自包含 HTML 适合评估内置回放；MHTML 可作为整页存档候选，但 Chrome 官方说明只能从文件系统、以顶层页面加载，不能假定可以在扩展 iframe 或 Blob URL 中直接阅读。需比较兼容、资源完整性、存档打开流程和依赖许可后再定格式。参考 [pageCapture API](https://developer.chrome.com/docs/extensions/reference/api/pageCapture)及 [SingleFile 作者项目](https://github.com/gildas-lormeau/SingleFile)，此处不决定集成某个库。

长任务必须能恢复；MV3 后台存在空闲终止和请求时限，不能把捕获或大附件上传只保存在内存中。参考 [Service worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。`unlimitedStorage` 影响扩展本地与 Web 存储的配额 / 淘汰约束，但不代表物理磁盘无限、卸载后仍保留或自动获得云备份，见 [扩展存储说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。

## 标签、浏览与索引

建议用稳定的标签 ID 与显示名称建立多对多关系。一篇网页仍只有一个项目归属，但可带多个标签；标签用于跨项目主题整理，不替代阅读状态。

候选基本能力：新建 / 选择标签、单篇和批量添加 / 移除、重命名、标签列表与数量、未打标签入口、按标签浏览。删除标签只移除标签和关联，不删除收藏；删除项目也不应删除仍被其他收藏使用的标签。重名、大小写、空白、标签合并和同步冲突规则在数据协议确认时一起定。

“索引”拆为两个层次，避免混为一个功能：

- **标签索引**：标签目录、计数、可点击进入的结果列表，可与项目、阅读状态及关键词组合。组合公式建议为“当前项目范围 ∩ 阅读状态 ∩ 关键词 ∩ 标签条件”。多标签内部支持“任一匹配 / 全部匹配”，默认哪一种仍待确认；计数明确是全库数量还是当前筛选结果。
- **内容检索**：当前元数据搜索可以扩展标签名称；正文全文搜索需正文快照及可重建的索引，另行评估分词、中文搜索、规模和首次构建成本。标签功能首期不默认包含全文搜索、自动打标或 AI 归类。

可举例验收：一篇属于“开发”项目、带“Vue”“待读”两个标签的网页，在全库“Vue”视图和项目内“Vue + 未读”视图都能出现；移动项目不丢标签，删除“Vue”标签不删网页。标签“待读”不自动改变系统阅读状态。

## 手机端边界

后续需确定具体浏览器、版本与安装渠道。支持安装 Chromium 扩展并不保证后台调度、侧栏、下载 / 文件打开、WebDAV 和 pageCapture 均与桌面一致；Edge 官方的 pageCapture 支持表目前列桌面平台，不能据此承诺手机整页捕获。

建议协议与 UI 解耦，保留使用普通扩展页面访问收藏和快照的可能性。手机端可分别评估“同步并阅读桌面已生成存档”和“在手机捕获新存档”，两者不绑定承诺。浏览器原生同步也不作为跨厂商手机互通的前提。

## 建议的验证顺序

WebDAV 先完成 [备份与恢复验收](#第一阶段备份验收)，再验证 [双向同步](#真实服务验收)。标签、快照、原生偏好同步各有验收边界，分别验证。

| 验证主题 | 通过标准 |
| --- | --- |
| WebDAV 备份与恢复 | 手动和自动备份均可从独立配置下载、预览并恢复。验证请求、流量和中断后重试 |
| WebDAV 双向同步 | 两台真实桌面设备或配置在并发、断网、删除、新设备接入和版本过旧时保留数据，并通过目标服务的写入与流量验收 |
| 原生同步 | 同账号同浏览器双电脑实测开关、离线恢复和配额失败；确认扩展 ID 与安装渠道；不把本地 `set` 成功视为远端验收 |
| 双类型快照 | 普通文章、登录后页面、动态页面、图片缺失、冻结 / 关闭 / 跳转、断网回放和空间不足；逐类型结果准确，失败不损坏已有收藏或旧快照 |
| 标签 | 单篇 / 批量编辑、组合筛选、移动项目、删除 / 合并标签、备份恢复与跨设备并发；重构 UI 不改变标签关系 |

## 后续验证与其他方向待确认项

1. WebDAV 第二阶段确认双向同步的提交方式。
2. ITER-026 确认 [配置同步实施计划](#配置同步实施计划) 的字段范围和首次接入规则。
3. 存档默认上传 / 下载范围、容量预算、最近一版或多版本、收藏删除后的保留方式，以及是否需要按站点规则。
4. 标签组合的默认“任一 / 全部”、计数范围、重名合并，以及“索引”是否还需要正文全文检索。

这些问题可分轮讨论；在尚未确认时保留候选，不把建议写成既定功能或立即开发任务。
