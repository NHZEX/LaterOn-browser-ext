| 方向 | 用户确认 |

## 当前项目事实与影响

- 正式收藏在 `chrome.storage.local`，包含网页、项目、阅读状态、封面、共享图标、排序及阅读位置；同一浏览器内部由[共享写队列](../../src/storage/coordinator.ts)协调。这不是跨设备同步协议，不能把本机的“后写覆盖”直接当作多设备冲突规则。
- 网页目前只保存元数据，没有正文快照或内容标签；搜索覆盖标题、摘要、来源和 URL，见[数据契约](../../src/storage/contracts.ts)、[备份核心](../../src/backup/core.ts)和[筛选规则](../../src/collection/filter.ts)。
- [现有备份](../backup-format.md)是 `lateron.collection` v1 JSON，导入会筛除未知字段，文件上限 50 MiB。新增标签、正文和存档必须一起设计导入导出，不能只加本地字段后假定旧备份已经能保存它们。
- [历史清理](../../src/background/maintenance.ts)会移除旧的 `contentHtml` 等正文遗留字段。新存档应有独立模型与迁移边界，不能直接复活旧字段。
- 项目继续表示网页所属的整理空间；内容标签表示可跨项目复用的主题。这里的“标签”不是浏览器标签页，也不等于未读 / 在读 / 已完成状态。

## 共同建议：数据留在本机，传输与附件分开

本地收藏始终可用；同步不可用不阻止收藏、编辑、阅读或标签整理。将信息分为收藏数据、附件和设备状态，分别确定同步规则：

| 数据 | 建议处理 | 需要补充的需求 |
| --- | --- | --- |
| 网页、项目、阅读状态、手工编辑、排序 | WebDAV 首期候选范围 | 同字段并发、项目删除和自动清理如何传播 |
| 封面、共享图标 | 跟随收藏同步，资源单独传输、校验和去重 | 失败时允许文字先可用，并显示附件待补齐 |
| 标签及网页与标签的关联 | 标签功能上线后纳入同一套同步规则 | 重名标签、同时添加 / 移除的合并方式 |
| 正文、整页存档及资源 | 快照功能上线后扩展；候选为上传可选、下载按需 | 是否默认上传两种存档、是否自动下载到每台电脑 |
| 主题、语言等少量偏好 | 可选原生同步，或由 WebDAV 管理；同一字段只有一个同步来源 | 哪些偏好跟随人，哪些跟随设备 |
| 阅读位置、筛选、侧栏宽度、当前网页、缓存、任务进度 | 默认按设备保存；阅读位置单独讨论 | 页面布局、视口及不同快照版本下的位置不等价 |
| WebDAV 凭据、设备身份、内容密钥 | 不进入普通收藏备份和浏览器原生同步 | 凭据保存、端到端加密及恢复方式 |

同一收藏库建议只启用一个收藏同步后端。原生同步与 WebDAV 同时使用时，明确各自负责的字段，避免相互回灌。同步不是历史备份；误删同步到所有设备后，仍需要可恢复的版本或独立备份。

## WebDAV：优先完善的需求

目标是让两台电脑在离线、并发编辑和删除后可靠收敛，而不是定时上传一份 JSON。

### 使用流程建议

1. 配置服务地址、独立目录和认证，先测试连接、读写及并发保护能力；凭据不写入项目文档或日志。
2. 首次接入展示本地与远端概要。远端为空可初始化；双方已有数据时先预览合并及冲突。覆盖本地或替换远端属于单独的显式操作，并先保留恢复副本。
3. 提供“立即同步”、最近成功时间、待上传 / 下载数量、失败原因和重试入口。本机写入成功不能显示成“已同步到其他设备”。
4. 自动同步为可配置能力：本机变更后合并触发、启动 / 恢复联网时检查、浏览器运行期间周期检查。间隔待定，不承诺后台永久在线或固定秒级到达。
5. 关闭同步保留本机数据；更换账号、目录或服务器视为接入另一收藏库，不能直接复用旧同步基线。

### 必须讨论清楚的规则

| 场景 | 建议规则 |
| --- | --- |
| A 修改标题，B 修改摘要 | 合并不同字段，保留双方改动 |
| A、B 同时修改同一个标题或移动到不同项目 | 检测冲突并保留双方版本供选择；不静默按设备时间取较新者 |
| A 删除，B 长期离线后上线 | 删除记录参与同步，旧副本不能让网页自动复活；删除与编辑并发保留恢复信息 |
| 删除后主动重新收藏相同 URL | 区分主动新增与旧副本重放，不能永久屏蔽相同 URL |
| 两台电脑分别收藏同一页面 | 复用现有 URL 身份规则匹配，处理 ID 映射和字段冲突，保留手工编辑 |
| 自动清理、删除项目、导入覆盖、清空收藏 | 明确哪些操作传播到其他设备；区分清理本机副本与删除同步收藏库，避免批量误删 |
| 远端超时、认证失败、文件损坏、未知格式 | 保留本机数据，停止错误覆盖；不能把读取失败当成“远端为空” |
| 网络恢复、浏览器退出或后台被回收 | 持久化待处理操作，恢复后幂等重试；不重复新增，不丢失已确认修改 |
| 一台设备版本过旧 | 对不认识的同步格式停止写入并提示升级，不能筛掉新字段后回传 |
| 图片或存档上传中断 | 未完成附件不能标为可用；恢复后补传，清理不能删掉仍被引用的资源 |

协议至少需要区分远端收藏库身份、协议版本、设备身份、记录修订、删除记录和本机待提交操作。本机现有 epoch 用于拒绝旧页面命令，不直接替代跨设备版本。不能单凭设备墙上时钟解决冲突；长期离线设备及删除记录回收也必须一起设计，不能到期直接清空删除记录。

并发写入候选采用服务器返回的强 ETag 和 `If-Match` 条件提交；首次创建使用 `If-None-Match: *`。发生前置条件失败后重新读取并合并，限制重试次数。ETag 防止覆盖别人刚提交的文件，但不替代业务冲突规则。真实服务若不支持或忽略条件写入，不能继续宣称具备安全的自动双向同步；需另选协议或限制为明确的手动备份 / 恢复模式。依据见 [HTTP 条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)。

认证、HTTPS / NAS 证书兼容、文件大小和请求频率要按目标服务验收。传输加密与端到端加密是不同需求；上传登录后正文和整页存档前，需确认是否允许服务端读取内容、如何管理解密口令和恢复密钥。

## 浏览器原生同步：能力与限制

这里指扩展的 `storage.sync`，不是浏览器书签同步，也不是让浏览器自动同步 `storage.local`。

Chrome 官方当前限制如下；统计包含键和序列化后的值，不能仅按网页条数估算：

| 限制 | Chrome 官方值 |
| --- | --- |
| 总容量 | 102,400 字节，约 100 KiB |
| 单个键值项 | 8,192 字节，约 8 KiB |
| 键值项数量 | 512；不是允许保存 512 篇完整网页 |
| 写入频率 | 每分钟 120 次、每小时 1,800 次，`set/remove/clear` 计入 |

超过限制会失败；拆键不能绕过总容量。`unlimitedStorage` 不扩大 `storage.sync` 的这些固定配额。建议首期只评估语言、主题等少量偏好，提供占用显示及限额失败提示，不放正文、图片和整页存档。若后续要支持精简收藏同步，必须单独确认字段、容量预算、分片一致性和超额时的完整性，不能静默只同步部分收藏。依据：[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。

Chrome 同步取决于用户登录、同步开关、网络和策略；离线写入不代表远端已收到。Chrome 文档描述其自身同步服务，Edge 使用其账号同步体系，因此规划不把 Chrome 与 Edge 的原生云空间当成互通渠道。Edge 支持 storage API 不等于所有发行渠道、账号及设备组合已验证；需要同浏览器两台电脑实测，另测固定扩展 ID、本地加载版 / 商店版及策略关闭同步的情况。参考 [Chrome 同步行为](https://developer.chrome.com/docs/extensions/mv2/reference/storage#storage-areas)、[Edge 同步](https://support.microsoft.com/en-us/edge/sign-in-to-sync-microsoft-edge-across-devices)、[Edge API 支持](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/api-support)。

## 快照：正文阅读版与整页存档

两种产物服务不同用途，属于同一次捕获记录，可分别成功或失败：

| 保存类型 | 目标 | 不能默认承诺的内容 |
| --- | --- | --- |
| 正文阅读版 | 离线查看正文、标题、作者等可提取信息及保存成功的正文图片，采用适合阅读的排版 | 对所有非文章页面都能正确提取全文 |
| 整页存档 | 保留捕获时已加载的页面内容、样式、布局和可保存资源 | 任意交互、流媒体、未加载的无限滚动内容、所有跨域嵌入都能复现 |

“完整”应描述实际捕获范围，而不是整站下载或未来内容。仅保存远程图片 URL 不算图片已离线。用户已登录且能访问的内容可在其授权的保存动作中捕获，但不承诺绕过登录、付费或访问限制。

### 配置与入口建议

将触发方式与保存类型独立配置，避免组合成大量难懂的开关：

| 设置 | 候选选项 | 建议默认 |
| --- | --- | --- |
| 自动触发 | 关闭自动捕获；收藏成功后自动捕获 | 收藏后自动排队 |
| 默认保存类型 | 正文阅读版；整页存档；两者 | 两者 |
| 单篇操作 | 立即保存、选择本次类型、重试缺失部分、更新快照、删除快照 | 使用全局默认，一次操作即可开始 |
| 已有收藏 | 手动补存，可选择范围，展示可捕获 / 需打开原文的数量 | 不在升级后自动遍历和打开所有旧网页 |
| 批量操作 | 批量保存或重试，允许取消，限制并发并展示逐项结果 | 不阻塞收藏列表 |

“仅手动”时仍允许选定默认类型；自动关闭不影响手动入口。按站点覆盖、定时刷新和多版本保留属于后续候选，不作为“可配置”自动推导出的首期承诺。

### 保存、阅读和管理建议

- 先提交收藏，再排队捕获。失败保留链接；正文和整页分别显示排队、处理中、可用、部分资源缺失、失败等结果，并提供原因与重试。
- 捕获时核对标签页仍存在且仍为目标页面；跨页跳转、关页、冻结和未加载页面要明确反馈，不静默激活大量标签页。后台重新抓 URL 不等于获得用户当前看到的动态或登录页面。
- 保留原始 URL、捕获时间、格式版本、资源校验和、大小和缺失信息。更新失败保留旧的可用快照；先建议每种类型保留最近一次成功结果，多版本作为另一个容量需求讨论。
- 提供明确的“阅读正文”“打开整页存档”“打开原网页”入口；断网时不依赖先访问原站才能找到快照。存档与手工编辑的标题、摘要分开管理，不因重新抓取覆盖用户整理。
- 内容与资源建议独立存储，例如扩展来源的 IndexedDB；普通收藏记录保存索引和引用，避免在列表整表中内嵌大段正文 / 图片。跨存储提交需有完成标记及中断恢复，不假定与 `storage.local` 存在共同事务。
- 展示单篇和总占用，允许删除快照而保留链接。单篇 / 全局容量上限、空间不足策略、删除收藏是否同时删除存档、自动清理是否应保留存档均待确认；默认不静默淘汰用户已保存内容。
- 阅读回放隔离原站脚本与扩展能力；不把原站 HTML 直接放进高权限扩展页面，不保存表单口令和会话凭据。离线回放默认不继续访问原站获取缺失资源，缺失需明确标注。
- 导出需区分收藏信息备份与含正文 / 整页资源的完整备份；旧 50 MiB JSON 不是完整存档方案，需另行评估带清单的资源包及兼容升级。

格式先做方案验证：自包含 HTML 适合评估内置回放；MHTML 可作为整页存档候选，但 Chrome 官方说明只能从文件系统、以顶层页面加载，不能假定可以在扩展 iframe 或 Blob URL 中直接阅读。需比较兼容、资源完整性、存档打开流程和依赖许可后再定格式。参考 [pageCapture API](https://developer.chrome.com/docs/extensions/reference/api/pageCapture)及 [SingleFile 作者项目](https://github.com/gildas-lormeau/SingleFile)，此处不决定集成某个库。

长任务必须能恢复；MV3 后台存在空闲终止和请求时限，不能把捕获或大附件上传只保存在内存中。参考 [Service worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。`unlimitedStorage` 影响扩展本地与 Web 存储的配额 / 淘汰约束，但不代表物理磁盘无限、卸载后仍保留或自动获得云备份，见 [扩展存储说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。

## 标签、浏览与索引

建议用稳定的标签 ID 与显示名称建立多对多关系。一篇网页仍只有一个项目归属，但可带多个标签；标签用于跨项目主题整理，不替代阅读状态。

候选基本能力：新建 / 选择标签、单篇和批量添加 / 移除、重命名、标签列表与数量、未打标签入口、按标签浏览。删除标签只移除标签和关联，不删除收藏；删除项目也不应删除仍被其他收藏使用的标签。重名、大小写、空白、标签合并和同步冲突规则在数据协议确认时一起定。

“索引”拆为两个层次，避免混为一个功能：

- **标签索引**：标签目录、计数、可点击进入的结果列表，可与项目、阅读状态及关键词组合。组合公式建议为“当前项目范围 ∩ 阅读状态 ∩ 关键词 ∩ 标签条件”。多标签内部支持“任一匹配 / 全部匹配”，默认哪一种仍待确认；计数明确是全库数量还是当前筛选结果。
- **内容检索**：当前元数据搜索可以扩展标签名称；正文全文搜索需正文快照及可重建的索引，另行评估分词、中文搜索、规模和首次构建成本。标签功能首期不默认包含全文搜索、自动打标或 AI 归类。

可举例验收：一篇属于“开发”项目、带“Vue”“待读”两个标签的网页，在全库“Vue”视图和项目内“Vue + 未读”视图都能出现；移动项目不丢标签，删除“Vue”标签不删网页。标签“待读”不自动改变系统阅读状态。

## 手机端边界

后续需确定具体浏览器、版本与安装渠道。支持安装 Chromium 扩展并不保证后台调度、侧栏、下载 / 文件打开、WebDAV 和 pageCapture 均与桌面一致；Edge 官方的 pageCapture 支持表目前列桌面平台，不能据此承诺手机整页捕获。

建议协议与 UI 解耦，保留使用普通扩展页面访问收藏和快照的可能性。手机端可分别评估“同步并阅读桌面已生成存档”和“在手机捕获新存档”，两者不绑定承诺。浏览器原生同步也不作为跨厂商手机互通的前提。

## 建议的验证顺序

这里只描述决策依赖，不是排期。WebDAV 按用户确认优先：先核对目标服务能力和首期数据范围，再验证双设备协议与恢复路径，最后讨论正式开发范围。标签、快照、原生偏好同步各自保留独立验收边界；WebDAV 首期不等待正文引擎或标签 UI 完成，但协议需能拒绝未知版本并支持以后扩展。

| 验证主题 | 通过标准 |
| --- | --- |
| WebDAV | 两台真实桌面设备 / 配置档案；并发、断网、删除、新设备接入、版本过旧及中断恢复后不丢数据；另在目标真实服务上验证条件写入 |
| 原生同步 | 同账号同浏览器双电脑实测开关、离线恢复和配额失败；确认扩展 ID 与安装渠道；不把本地 `set` 成功视为远端验收 |
| 双类型快照 | 普通文章、登录后页面、动态页面、图片缺失、冻结 / 关闭 / 跳转、断网回放和空间不足；逐类型结果准确，失败不损坏已有收藏或旧快照 |
| 标签 | 单篇 / 批量编辑、组合筛选、移动项目、删除 / 合并标签、备份恢复与跨设备并发；重构 UI 不改变标签关系 |

## 下一轮可集中确认的问题

1. WebDAV 服务商及首期收藏规模、可用空间；是否要求端到端加密、如何恢复口令。此阶段不需要提交账号密码。
2. 收藏与项目删除、自动清理、清空和备份覆盖哪些操作跨设备传播；冲突是否接受保留双方版本后手动选择。
3. 阅读位置是否跨设备；主题和语言走原生同步还是 WebDAV。每个字段选定单一同步来源。
4. 存档默认上传 / 下载范围、容量预算、最近一版或多版本、收藏删除后的保留方式；是否需要按站点规则。
5. 标签组合的默认“任一 / 全部”、计数范围、重名合并，以及“索引”是否还需要正文全文检索。

这些问题可分轮讨论；在尚未确认时保留候选，不把建议写成既定功能或立即开发任务。
