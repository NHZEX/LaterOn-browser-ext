## 维护与历史

只保留会影响后续维护的决策：决定、原因、适用边界；被替代后更新或删除。局部算法的原因写在对应代码注释中。讨论过程、逐轮测试日志和已完成的实施步骤由提交历史承接，不再追加月度流水。

任务收尾、相关提交和发版是临时文档的复查节点；通常在同批改动中把有效约束并入正式文档、剩余任务并入 roadmap，删除过程稿及过时引用。

遇到评审未结束、等待用户验收或跨阶段实施时，可以暂留方案。一个任务尽量只保留一份，放在 `docs/plans/`，开头简要写明关联任务、保留原因、下次复查节点和退出条件，例如“关联 ITER-XXX；待验收；下次发版前复查；验收完成后提取约束并删除”。任务状态仍只在 roadmap 维护，必要时链接该方案，不另建临时文档台账，也不加入默认必读清单。到节点后必须处理或更新保留原因和下次节点，日期只用于复查提醒，不自动触发删除。

删除前确认有价值内容已归入正式文档或提交历史；未提交的新草稿必须先完成归纳，或确认已无保留价值。发布记录只保留最近一次本机部署的核对结果，历史产品变化留在 CHANGELOG。交付说明记录本轮范围、验证结果和剩余事项。
