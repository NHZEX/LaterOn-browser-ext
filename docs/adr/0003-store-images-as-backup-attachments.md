# ZIP 快照按图片内容保存附件

含图备份会重复保存相同的内嵌图片，压缩文本无法稳定去掉这些重复。我们将网页封面、项目封面和站点图标的原始图片放入各自的 ZIP，同一份快照只保存一份相同图片。远程图片保留链接，每份 ZIP 延续[可独立恢复的快照](0002-store-webdav-backups-as-self-contained-snapshots.md)的边界。

## 格式与升级

- `manifest.json` 的 `version` 为 `2`，用于识别新版 ZIP。`backup.json` 保存收藏数据及图片引用，`images/<SHA-256>.<扩展名>` 保存原始图片。
- 仅 WebDAV 生成新版 ZIP，本地可导入新版 ZIP。本地 JSON 格式和导入导出保持原有行为。新版读取器遇到旧 ZIP 时提示格式不支持。
- 新 ZIP 沿用 `backups/<备份来源>/` 及文件命名。旧 ZIP 暂留时仍参与现有列表和自动轮转，用户可自行移除。升级后首份新版自动备份等常规间隔到期并满足流量预算再生成，即使收藏内容未变。

## 下载与恢复

- 主数据可读且有附件缺损时，「下载备份」保存同一次 WebDAV 请求收到的原包，并提示缺损。恢复预览列出缺损附件数量及受影响的收藏和项目数量。用户明确接受缺图后，按所选的合并或覆盖模式继续，保留可读取的图片并按现有规则显示占位图。覆盖恢复仍先保留本机恢复副本。主数据损坏时停止恢复。
- 保持现有可恢复规模。校验 ZIP 总大小、实际解包量和恢复数据大小。写包时检查完整恢复所需的数据大小，避免产生同版本恢复不了的快照。缺图恢复仍执行大小限制。
