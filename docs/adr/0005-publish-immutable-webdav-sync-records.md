# 用不可变发布记录发现 WebDAV 同步快照

状态：隔离构建用于协议回归；普通构建仅提供默认关闭、按目录准入的手动试用，不宣布正式支持。本决策只替换 [ADR 0001](0001-merge-webdav-collection-changes.md) 的覆盖式发布协议，不迁移旧目录。

覆盖式设备索引在目标入口上允许晚到的第 7 代盖掉已确认的第 8 代，首次接入没有历史可用来察觉回退。候选协议仍先写 gzip 全量快照，再写小 JSON，但每代写入独立路径；读取方按设备从目录所见的发布记录中选择最大代次。不把可覆盖的 `head` 作为索引、提示或回退路径，也不依赖 ETag、锁或条件覆盖。收藏合并、找回、手动同步与独立 ZIP 备份不变。

## 协议边界

- **写入。** 新协议只使用新的专用目录，不就地转换旧目录或混读两代格式。同一库内，快照与发布记录的文件名均由 `deviceId`、`seq`、`stateHash` 构成；目录路径不取自远端载荷。这样旧代次或同代不同状态都不会写到新记录及快照的路径。继续持久化已分配代次和轻量待发布意图，只允许用同名路径重试相同逻辑内容。先核验快照身份和摘要再发记录；回读匹配且目录发现将它选为本设备的最新记录后，才向用户确认本次发布。已被更高代次取代时不补写旧记录。仍用 `collectionId + bindingId` 拦住旧回包和尚未发出的请求。
- **读取。** 从严格校验的目录结果中按设备分组，按数值选最大 `seq`，只读所选记录。选中代次出现两个不同摘要、文件名与载荷或库身份不符、缺少已知设备或低于已确认代次，都要暂停。当前候选掉失或其快照返回 `404` 时，整轮最多重新发现一次；相关设备必须得到严格更新的有效代次，不能退回到较低代、空库或部分设备后继续合并。所选快照能直接读取但未列出，同样视为清单不完整。
- **避免回声。** 无待确认发布且未暂停时，仍核验目录和所选发布记录；仅当同一份发布已经校验并合入本机状态、且快照仍列在目录中，才跳过下载。已合入的状态由确定性合并和删除记录保留；新发布即使摘要相同，也要下载校验身份和摘要。合并后若所选有效发布已有同一 `stateHash`，不重复发布，即使本机从未发布过。纯接收不写远端；此前失败的本机清理留待下一次无变化检查或本机确认发布后重试。
- **留存。** 只有新记录及快照确认且目录可发现后，才尽力保留本机已确认的当前及上一代：先删旧发布记录，再删它引用的快照；清理可重试，不猜删他端或归属不明的对象。尚未确认的孤立快照、清理失败和晚到旧记录都可能占用目录名额；不为凑足配额盲删，也不回收删除记录。

## 启用约束

不同路径解决的是同路径覆盖；这一结论适用于坚果云直连和 OpenList，不必在每种服务或挂载上重跑完整协议回归。[RFC 4918 §9.1](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1) 要求在请求深度下列出成员，但实际入口可能缓存、分页或漏列；结构正确且低于上限的 `207`，也不能让全新设备识别无提示的漏列。达到上限、分页未完成或已知记录矛盾时仍须停下，不当作空库或部分状态继续合并。

手动试用只要求在拟用入口的专用空目录做一次冒烟：一端确认发布，另一套全新配置完成预览与接入，并核对同一代次及该代新增的收藏。单文件 `GET` 可读或旧设备读取成功不能替代这一步。通过只证明该入口在所测条件下可见，不保证以后不会静默漏列；未测或未通过的入口不开放试用、不标为已验证，独立 ZIP 备份不受影响。没有额外入口或无法重现限流，不阻塞后续开发；不为手动试用逐挂载压测或要求证明普遍的目录完整性。

普通构建只允许 `VITE_LATERON_SYNC_TRIAL_DIRECTORY` 指定的一个完整专用目录地址，不按域名或服务商放行。准入地址必须与冒烟的目录一致；仅可在不分发的隔离配置中用候选地址试跑。未设地址时不能创建或加入；不在构建变量中填写凭据。每个浏览器配置仍须主动开启并明确填写目录及独立同步凭据。关闭试用同时本机解绑、清除该绑定凭据，不删除远端文件；已经发出的请求无法撤回。保留独立 ZIP 备份；使用 OpenList 时关闭同步目录缓存。
