# 用不可变发布记录发现 WebDAV 同步快照

状态：用于隔离构建，未放行正式同步。本决策只替换 [ADR 0001](0001-merge-webdav-collection-changes.md) 的覆盖式发布协议，不迁移旧目录。

覆盖式设备索引在目标入口上允许晚到的第 7 代盖掉已确认的第 8 代，首次接入没有历史可用来察觉回退。候选协议仍先写 gzip 全量快照，再写小 JSON，但每代写入独立路径；读取方按设备从目录所见的发布记录中选择最大代次。不把可覆盖的 `head` 作为索引、提示或回退路径，也不依赖 ETag、锁或条件覆盖。收藏合并、找回、手动同步与独立 ZIP 备份不变。

## 协议边界

- **写入。** 新协议只在新的专用目录和隔离构建中验证，不就地转换旧目录或混读两代格式。同一库内，快照与发布记录的文件名均由 `deviceId`、`seq`、`stateHash` 构成；目录路径不取自远端载荷。这样旧代次或同代不同状态都不会写到新记录及快照的路径。继续持久化已分配代次和轻量待发布意图，只允许用同名路径重试相同逻辑内容。先核验快照身份和摘要再发记录；回读匹配且目录发现将它选为本设备的最新记录后，才向用户确认本次发布。已被更高代次取代时不补写旧记录。仍用 `collectionId + bindingId` 拦住旧回包和尚未发出的请求。
- **读取。** 从严格校验的目录结果中按设备分组，按数值选最大 `seq`，只读所选记录。选中代次出现两个不同摘要、文件名与载荷或库身份不符、缺少已知设备或低于已确认代次，都要暂停。当前候选掉失或其快照返回 `404` 时，整轮最多重新发现一次；相关设备必须得到严格更新的有效代次，不能退回到较低代、空库或部分设备后继续合并。无变化时不下载快照、不写远端。
- **留存。** 只有新记录及快照确认且目录可发现后，才尽力保留本机已确认的当前及上一代：先删旧发布记录，再删它引用的快照；清理可重试，不猜删他端或归属不明的对象。尚未确认的孤立快照、清理失败和晚到旧记录都可能占用目录名额；不为凑足配额盲删，也不回收删除记录。

## 启用约束

不同路径解决的是同路径覆盖，不保证后台服务列出所有新对象。[RFC 4918 §9.1](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1) 要求在请求深度下列出成员，但实际入口可能缓存、分页或漏列；结构正确且低于上限的 `207`，也不能让全新设备识别无提示的漏列。必须逐入口确认目录列举完整性和已确认记录对新客户端的可见性：达到上限、分页未完成或已知记录矛盾时停止，不能把它当空库；在无法确认完整性或确认后仍可能静默漏列的入口保持禁用。两次列表相同或单文件 `GET` 可读均不能代替这项验证。
